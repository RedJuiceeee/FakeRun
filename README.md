# FakeRun

中文 Android 本地模拟定位应用。手工绘制闭合路线，生成一次完整预览后，通过系统开发者选项授权的 test provider 输出 WGS84 GPS / network 位置。应用保留 Android 的 mock 标记。

当前版本 **1.0.1（versionCode 2）**：[下载 Release 安装包](https://github.com/RedJuiceeee/FakeRun/releases/tag/v1.0.1)。本次发布用户已核验的 `FakeRun-1.0.1-debug.apk`，使用 Android 调试签名，不是正式 release 签名包。Android 8.0 及以上可安装；安装与使用步骤见下文。签名、校验值和验证范围见 [1.0.1 发布说明](docs/release-1.0.1.md)。

首版已实现路线编辑与保存、有限圈数、平滑跑步/步行速度、连续横摆与避让、GPS 观测漂移、全程随机驻留、集中步行比例求解、前台服务、暂停/继续/结束。已通过百度地图鉴权、算法测试和 Android 模拟器上的完整两圈场景；实际范围与真机待验收项见 [本轮验证记录](tests/manual/verification.md)。没有 AK 的构建不会初始化地图，不能视为地图鉴权成功。

## 构建与 AK

要求 JDK 17 或 21、Android SDK Platform 36、Build Tools 35.0.0。工程锁定 AGP 8.10.1、Gradle 8.12、Kotlin 2.1.20、百度地图 SDK 8.2.0。最低 Android 8.0（API 26），targetSdk 36；单个 `app` 模块，原生 XML 界面。

1. 将 `local.properties.example` 复制为 `local.properties`，填写 `sdk.dir`。Windows 路径使用 `/` 分隔，并将盘符冒号转义为 `\:`（见示例），文件不要提交。
2. 在百度地图开放平台申请 **Android SDK** 类型 AK；填写包名 `com.fakerun.app`，绑定安装 APK 的签名 SHA-1。
3. 在 `local.properties` 填写 `BAIDU_MAP_AK=自己的AK`。AK 通过 Manifest 占位符注入。AK 及签名私钥不进入版本管理。
4. 执行 `gradlew.bat :app:signingReport` 查看当前调试签名 SHA-1。不同机器的 debug 签名通常不同；换签名后必须更新 AK 绑定并重新构建。
5. 执行 `gradlew.bat :app:assembleDebug`。APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。使用 `adb install -r` 或复制到手机安装。

Linux/macOS 使用 `./gradlew`。不带 AK 仍可构建并运行纯算法测试，但地图编辑和地图鉴权尚不能验收。release 默认不包含签名私钥，可使用用户自己的 Android 签名流程签署 `assembleRelease` 的产物，并在百度控制台绑定对应 SHA-1；不要把私钥或密码写进工程。

百度免费权益和个人非商业使用范围以用户控制台与当期条款为准。应用只引入地图组件及其必需的基础依赖，不调用路线规划、检索、导航、百度定位或 Google Play Services。

## 手机准备与操作

1. 打开应用“准备”页，阅读并同意隐私说明后启用百度地图。拒绝时不创建 MapView。路线/参数保存在应用私有目录，地图 SDK 会联网；清除应用数据可撤回同意并删除本地内容。
2. 申请精确定位权限并打开系统定位。Android 12+ 同时请求 coarse/fine，需选择精确定位。通知权限拒绝时仍保留系统前台服务通知，可从应用内结束。
3. 在系统开发者选项的“选择模拟位置信息应用”中选 FakeRun。此资格不是普通运行时定位授权；应用不会自动替你选择。
4. 到“路线与参数”开启绘制。地图点击添加节点，长按节点拖动，点击节点可编辑 GCJ-02 数值或删除。地图可拖动缩放；相邻节点直线连接，不自动贴路。撤销可恢复最近编辑。
5. 至少 3 个节点后点击“闭合路线”。末点到首点是显式连接线；平滑后每圈至少 100 米，相邻节点至少 2 米，最多 500 节点，总展开中心线不超过 50 km。近乎折返、边界附近或不支持区域会指出原因，不能开始。
6. 保存路线时输入名称；列表可打开或删除多条记录。生成预览也保存最近参数。私有数据损坏时明确报错并保护原文件，不能默默覆盖。
7. 配置后点击“生成完整预览”。后台计算可取消。预览列出中心/人物距离、预计时间、每次停止位置与抽样时长、集中步行区域、避让及偏移。地图蓝色为中心线、绿色为人物路径、紫色为步行区域；实时人物为绿标，报告 GPS 为橙标。
8. 确认预览后点“开始模拟”。首次位置直接是选择的路线起点，不模拟真实位置到起点的运动。运行中冻结本次路线与配置；表单修改作用于下一次运行。
9. 应用退到后台或息屏时前台服务继续运行。暂停等待当前速度锚点后平滑减速，暂停期间人物不移动、GPS 漂移仍继续；继续时验证并重新适配剩余时间表，保留原停止位置和时长。干预后显示实际步行比例。
10. 页面“平滑结束”在锚点接合后减速并取消会话；通知/页面“立即结束”立即清理模拟 provider、通知和唤醒锁。运行失败、权限撤销或回调迟到超过 1 秒时停止，展示原因；进程被杀后不自动续跑，重新打开时准备页单独显示上次会话记录，避免被地图鉴权消息覆盖。

## 参数与统计口径

| 参数 | 默认 | 范围/行为 |
| --- | --- | --- |
| 圈数 | 1 | 1～100，全程有限次数 |
| 跑步基准 | 10 km/h | 4～20；巡航在基准 ±2 km/h 内平滑浮动 |
| 中途停止 | 0 | 0～20；全程合计，不按圈重复 |
| 停留基准 | 10 秒 | 3～120；每次在 `[max(3,基准-5), min(120,基准+5)]` 内独立整数抽样 |
| 步行基准 | 5 km/h | 1～7，低于跑步基准；浮动 ±1 km/h，下限 0.5 |
| 步行占比 | 0% | 0～80%，整数百分点；非零时一个集中步行区 |
| 人物横向上限 | 3 米 | 0～3；0 关闭横摆与避让 |
| 自然横摆/避让/GPS 漂移 | 开 | 自然横摆最大 0.35 米；避让峰值 1.2～2.5 米；GPS 半径 2 米 |
| 同时模拟 network | 开 | 与 gps 同位置、速度、精度和时间戳；接入失败明确停止 |
| 模拟椭球高度 | 55 米 | -500～9000 米；平坦路线基准叠加 ±1.5 米连续观测误差，不是测量海拔 |
| 模拟 GPS 卫星数 | 7 | 0～32 整数，本次固定；GPS extras 字段，不产生真实 GNSS 卫星状态 |

模拟卫星数 ≥4 时水平精度平滑变化于 4～8 米，垂直精度为 3～6 米；设为 0～3 时使用弱信号观测档位，水平/垂直精度均为 20～40 米。高度和精度在暂停、驻留期间继续变化，人物水平路程与速度不受影响。升级旧版参数文件时自动补齐高度 55 米、卫星 7 颗；非法新字段仍报错。

步行占比的分子仅为 `WALK` 巡航时间，分母是全部移动时间（含起步、停止减速和走跑切换），排除驻留与用户暂停。无干预完整运行的计划误差不超过 1 个百分点。每段步行巡航至少 30 秒，两次停留之间至少 10 秒巡航；不可行组合明确拒绝，不修改用户次数或占比。

速度沿人物实际弧长积分，圈数按中心线累计进度判断；GPS 观测误差不累加到行进路程。人物偏移和 GPS 误差分别建模，驻留时人物速度为零。速度/加减速使用五次平滑曲线，纵向加速度 ≤0.8 m/s²、变化率 ≤0.6 m/s³；这些限制不等于全方向加速度限制。

## 开发与验证

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
```

全部测试源码在根目录 `tests/`，`test` / `androidTest` 源集与资源已映射。普通 APK 没有任何对 `tests/` 的依赖；删除该目录只会失去相应测试，不需要实际删除来证明。

`tests/unit` 使用合成路线和固定 seed 检查坐标、弧长、速度边界/加速度、停止、步行比例、GPS 分层、重现性与控制状态。`tests/device` 包含独立系统位置读取器、JSON 保存和服务操作验收。设备最终步骤见 [手工验收](tests/manual/acceptance.md)。原始构建输出、APK 和设备日志不提交；简洁结论保存在验证记录。

生产代码按 `ui / model / geo / simulation / location / data` 放置。排程与引擎无 Android 依赖，运行循环只在服务线程内执行，5 Hz 使用单调时钟实际经过时间。数据文件为 UTF-8 无 BOM JSON。

## 限制

首版保守限制为大陆普通城市区域，轮廓附近、港澳台及海外拒绝转换；不宣称边界地理精度或百度官方逆转换。狭窄道路可主动降低横向上限。没有足够直线保护窗口时预览说明不能生成完整避让。路线需要联网看地图，已生成的时间表与定位注入在本机运行。

模拟高度、卫星 extras 和弱信号精度档位仅作为定位观测字段输出。不包含 Root、Hook、隐藏 mock 标记、第三方检测绕过、真实 GNSS/其他传感器回调替换、账号、服务器或成绩上传。厂商后台管理、真实手机及融合定位接口仍需要各自验收；地图图标移动不能证明系统位置注入。

Honor Magic 8 Pro / Android 17 上，1.0.0 已复现步道乐跑 4.1.7 准备页不采用系统模拟位置：真实前台服务及 gps/network/passive 读取对照通过，目标定位处理的具体分支仍未确认。旧版证据见 [定位兼容排查记录](tests/manual/location-compatibility.md)。

1.0.1 参考 GoGoGo 修正定位来源属性：覆盖前保留设备原 gps/network 的来源、功耗和精度类型，并声明模拟高度/速度/方向输出能力。按用户追加要求加入可配置高度、GPS 卫星 extras 和弱信号观测档位。设备缺少 network 时明确提示关闭相应开关并重新生成预览。用户于 2026-10-10 反馈“核验通过”，并确认发布本次已核验的 debug APK；未提供逐项结果，因此不据此宣称所有第三方应用兼容或弱 GPS 提示均已解决。[参考对照与无 ADB 测试步骤](tests/manual/gogogo-reference.md)保留发布前的验证证据与步骤。

第三方来源和许可证见 [docs/third-party.md](docs/third-party.md)。完整产品规则以 `plan.md` 为准。
